Building the released KICK application
=====================================

See ../README.md for desktop dependencies, tests, data/resource paths and current
limitations. AudIO and ComProtocol now use the released sibling directories and
local JUCE/serial adapters; private platform repositories are not needed.

Desktop Linux/macOS, from the repository root:

    cmake -S Kick -B /tmp/kick-build -DKICK_JUCE_PATH=/path/to/JUCE-7.0.12 \
        -DCMAKE_BUILD_TYPE=Debug -DTIMESTAMP=OFF \
        -DKICK_BUILD_PLATFORM_TESTS=ON -DKICK_CLAP_BUILD_TESTS=ON
    cmake --build /tmp/kick-build --parallel 2
    ctest --test-dir /tmp/kick-build --output-on-failure

Use xvfb-run -a before CTest on a headless Linux host. Desktop builds keep board
operations disabled. Supply your own licensed samples, SoundFont and font files.

Building a board SDK
====================

In the companion Buildroot tree, build the KICK configuration and SDK:

    make KTKick_defconfig
    make sdk

Install/relocate the generated SDK according to its Buildroot instructions. No
prebuilt SDK archive is included in this release.

Cross compiling for the physical KICK
===================================

From the repository root, with CMake/Ninja and a JUCE 7.0.12 checkout available:

    export TOOLCHAIN_FILE=/path/to/sdk/share/buildroot/toolchainfile.cmake
    bash Kick/buildApp.sh Release -DKICK_JUCE_PATH=/path/to/JUCE-7.0.12

The script enables KICK_ENABLE_HARDWARE and builds Kick/Build/Release/bin/Kick.
KICK_BUILD_JOBS sets the build concurrency (default 2). Additional arguments go to
CMake. A manual cross configure must pass -DKICK_ENABLE_HARDWARE=ON as well.
The Linux touchscreen patch is applied to an owned build copy of JUCE.

Deploy/run only on the intended board image. Desktop/QEMU tests do not establish
board boot, physical I/O compatibility, callback deadlines or ALSA xrun limits.
See ../clap_host/README.md for the offline/device benchmark workflow.
